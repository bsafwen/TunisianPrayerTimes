## How the timings will be generated

No official Qaloun timings exist for Trabelsi (mp3quran's timing API covers only his Hafs reading — verified live today). So, exactly like Ayoub (the closest precedent: Tunisian, Qaloun, no official data), timings will be produced with the **Quranic Universal Aligner API** (`aligner.qud.dev/api/v1`, open, no key) via forced alignment against the Qaloun mushaf text:

1. For each surah 1–114, upload the **converted** 64 kbps MP3 (the exact file that ships) to `POST /align/audio` with `riwayah=qalun`, `model_name=Large`.
2. Reshape the session to one segment per verse (`/sessions/{id}/split`, `max_verses=1`) and/or fetch word timestamps (`/sessions/{id}/timestamps`, granularity=words) — pilot surah 001 first to inspect the response shape; Ayoub's intervals were built from word timings.
3. Build each ayah's `startMs`/`endMs` from the alignment; `durationMs` via `ffprobe` of each converted file; clip a final-verse overrun of a few hundred ms to `durationMs` (Hosary's policy). Untimed basmala/intro audio is fine per the docs.
4. Validate with the docs' `check_timings.py` (verse counts vs `quran/index.json`, ordered non-overlapping intervals within durations) — must print `timings.json is valid`. Widespread verse-count mismatches would mean the recording is the Hafs edition → stop and report.

The script is resumable (raw responses cached per surah in `work/trabelsi-align/`, git-ignored; retries with backoff on 429/503; CPU fallback accepted) and runs in the background (~10–30 min alignment + upload time).
